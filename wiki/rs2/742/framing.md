# Framing
Revision 742. Nested sources `a6b67f4`. Sizes are the constructor arguments. `ServerProt.values()` is declaration order, and the constructors are opcode 0 through 163, so the opcode is the array index. `ClientProt` has no `values()` array; the client writes `ClientProt.id`.
Inbound framing is `Client.handleServerProt` at builds/rs2/742-2012-11-07/src/client/src/main/java/Client.java:6441. When `packetType` is null the client reads one byte, or a second byte when `PacketBit.isIsaac1or2` is true, then `gIsaac1or2`. The opcode indexes `ServerProt.values()`. `size == -1` reads one more byte (`data[0] & 0xFF`) as the payload length. `size == -2` reads `g2()` (`u16be`) as the payload length. The payload is then exactly that many bytes. A size of 0 has an empty payload. There is no second length array.
Outbound `ClientMessage.createMessage` writes `pIsaac1(opcode)` and does not write a length. Variable client packets write their own length with `psize1` (`u8`, back-patched) or `psize2` (`u16be`, back-patched), or, for `EVENT_KEYBOARD`, a leading `p2` that is the `-2` length. `ServerConnection.queue` copies `buf.pos` bytes. It does not add another length.
ISAAC direction: `pIsaac1` adds `Isaac.opIsaac12()` to the opcode. `gIsaac1or2` subtracts `opIsaac12()` from each opcode byte. `isIsaac1or2` peeks with `opIsaac10` and does not consume. `Isaac.opIsaac12` and `opIsaac10` return 0 when `Client.ENABLE_ISAAC` is false. This tree sets `ENABLE_ISAAC` false at builds/rs2/742-2012-11-07/src/client/src/main/java/Client.java:22, so the addend is 0. The direction is still add on the way out and subtract on the way in. Login does not use ISAAC. After the login block, `randomOut = new Isaac(seed)` and each of the four seed ints is increased by 50 before `randomIn = new Isaac(seed)` (builds/rs2/742-2012-11-07/src/client/src/main/java/LoginManager.java:531).
`PacketBit.gBit` is LSB-first inside the current byte: it accumulates `BITMASK[bits left in the byte]` from `data[byte]`, then moves to the next byte (builds/rs2/742-2012-11-07/src/client/src/main/java/PacketBit.java:54). `bits()` sets `bitPos = pos * 8`. `bytes()` sets `pos = (bitPos + 7) / 8`.
Plain integers are big-endian: `p1`/`g1` u8, `g1b` i8, `p2`/`g2` u16be, `g2s` i16be, `p3`/`g3` u24be, `g3s` i24be, `p4`/`g4s` u32be, `g5` is `g1` then `g4s` (u40be), `p8`/`g8` u64be. `ip2`/`p2_alt1`/`g2_alt1` are u16le. `ip4`/`ig4`/`p4_alt1`/`g4s_alt1` are u32le. `ig8` is two `ig4` values with the first dword as the low half (u64le).
Alt widths are not a second endianness name. `g1_alt1` is `byte - 128`. `g1_alt2` is `-byte`. `g1_alt3` is `128 - byte`. `p2_alt2` writes the high byte, then the low byte plus 128. `g2_alt2` is u16be with the low byte minus 128. `p2_alt3` writes the low byte plus 128, then the high byte. `g2_alt3` is u16le with the first byte minus 128. `g3_alt1` is u24le. `g3_alt2` is `(b0<<16)+b1+(b2<<8)`. `g3_alt3` is `(b0<<8)+(b1<<16)+b2`. `g4s_alt2` is `(b0<<8)+b1+(b2<<24)+(b3<<16)`. `g4s_alt3` is `(b0<<16)+(b1<<24)+b2+(b3<<8)`. The matching `p*` methods write those byte orders. Signed `g2s_alt*` use the same bytes and then subtract 65536 when the result is above 32767. Citations: builds/rs2/742-2012-11-07/src/client/src/main/java/Packet.java:81 and builds/rs2/742-2012-11-07/src/client/src/main/java/Packet.java:572.
`gFloat` is `Float.intBitsToFloat(g4s())`, a big-endian float (`f32be`) (builds/rs2/742-2012-11-07/src/client/src/main/java/Packet.java:350). `pjstr`/`gjstr` are CP1252, terminated by 0 (`jstr`). `pjstr2`/`gjstr2` write or require a leading 0 and then a nul-terminated CP1252 string (`jstr2`). `gUTF8` requires a leading 0, then `gVarInt` length, then that many UTF-8 bytes. `gSmart1or2` is u8 if the next byte is below 128, otherwise u16be minus 32768. `gSmart2or4` is u16be, or u32be with the top bit cleared when the next byte is negative. `gSmart2or4null` maps u16be 32767 to -1.
`tinyenc` / `tinydec` are XTEA, delta `0x9e3779b9`, 32 rounds, on 8-byte blocks (builds/rs2/742-2012-11-07/src/client/src/main/java/Packet.java:484). `rsaenc` writes `u16be` length and the byte array of `BigInteger.toByteArray()`. `Client.ENABLE_RSA` is false, so `modPow` is skipped and the block is the original bytes (builds/rs2/742-2012-11-07/src/client/src/main/java/Packet.java:530).
`ZoneProt` is not a top-level opcode. `valueServerProt124` reads a zone base and then `ZoneProt.opZoneProt13()[g1()]`. The `ZoneProt(int)` constructor discards its argument (builds/rs2/742-2012-11-07/src/client/src/main/java/ZoneProt.java:51). Those integers are not a size table. Payload bytes are the reads in `handleZoneProt`.
